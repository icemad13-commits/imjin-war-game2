## 업데이트 내용 ② (이전 버전)

이미 한 번 깃허브에 올려서 쓰고 계셨다면, 아래 내용을 참고해서 바뀐 파일만
다시 올리거나(또는 폴더 전체를 통째로 다시 올려도 됩니다) 반영해 주세요.

1. **평양성 전투 수정**: 포탄이 곡선을 그리며 날아가는 게 잘 안 보이던 문제와,
   맞춘 것 같은데 포루가 안 부서지던 문제를 고쳤습니다. 이제 조준할 때 점선으로
   실제 궤적을 미리 보여주고, 포루(붉은 원 표시) 몸통 어디에 맞아도 파괴됩니다.
2. **첫 화면 배경 복원**: 타이틀 화면에 예전 버전처럼 흐릿한 한반도 지도와
   전투 이동 경로, 그리고 병사·거북선·판옥선 삽화가 배경으로 다시 들어갔습니다.
3. **명량해전 수정**: 대장선이 좌우 벽에 부딪혀도 화살에 맞은 것과 똑같이
   -25점이 깎입니다. 왜선의 화살 공격 빈도도 이전의 2배로 늘었습니다.
4. **행주산성 확인**: 파란 테두리 방패부대는 신기전으로는 절대 죽지 않고
   돌 던지기로만 처치할 수 있도록 다시 한번 확인하고, 신기전이 방패부대에게
   전혀 통하지 않는다는 것을 화면에 "무효!" 표시로 더 분명하게 보여주도록
   보완했습니다.
5. **최종 승리 요인을 서술형으로 변경**: 4칸으로 나뉘어 있던 입력창을 없애고,
   하나의 큰 칸에 자유롭게 글로 쓰는 서술형으로 바뀌었습니다. 이에 맞춰
   `apps-script/Code.gs`의 구글 시트 저장 방식도 "승리요인1~4" 네 칸이 아니라
   "승리 요인 서술" 한 칸으로 바뀌었습니다.
   - ⚠️ **이미 구글 시트를 연결해서 쓰고 계셨다면, `apps-script/Code.gs` 코드를
     이번 버전 내용으로 다시 붙여넣고, "배포 → 배포 관리 → 연필 아이콘 →
     버전: 새 버전"으로 다시 배포해야 반영됩니다.** (주소는 그대로 유지됩니다)
     자세한 방법은 아래 "3. 구글 시트와 연결하기"를 참고하세요.

바뀐 파일 목록: `index.html`(변경 없음), `css/style.css`, `js/app.js`,
`js/games2.js`, `js/data.js`, `js/sync.js`, `apps-script/Code.gs`. 잘 모르겠다면

## 0. 이 폴더 안에는 무엇이 들어있나요?

```
imjin-war-game2/
├─ index.html          ← 앱의 시작점 (이 파일 하나로 전체 앱이 열립니다)
├─ css/style.css        ← 화면 디자인
├─ js/                  ← 게임 로직 (여러 파일로 나뉘어 있습니다)
├─ assets/images/       ← 그림 파일들 (.webp) ← ★ 아래 "이미지 안내" 꼭 읽어주세요
├─ apps-script/Code.gs  ← 구글 시트에 붙여넣을 코드
└─ README.md            ← 지금 보고 계신 이 설명서
```

절대 어려운 조작이 필요 없습니다. **이 폴더를 통째로 깃허브에 올리기만 하면** 나머지는
Vercel이 알아서 홈페이지로 만들어 줍니다.

### ★ 이미지 파일이 깨지지 않게 하는 방법 (중요)

이 앱은 예전 버전(아트팩트)과 달리, 그림을 `assets/images/` 폴더 안의
**진짜 이미지 파일(.webp)** 로 관리합니다. 그래서 지켜야 할 규칙이 딱 3가지입니다.

1. **파일 이름을 바꾸지 마세요.** `js/images.js` 파일이 파일 이름으로 그림을 찾기 때문에,
   이름이 하나라도 다르면 그 그림만 화면에 나타나지 않습니다. (에러가 나지는 않고, 그냥 그
   부분만 비어 보입니다.)
2. **폴더 구조를 그대로 유지하세요.** `assets/images/` 안에 있는 8개의 `.webp` 파일을
   절대 다른 폴더로 옮기지 마세요.
3. **그림을 바꾸고 싶다면, 같은 이름의 `.webp` 파일로 "교체"만 하세요.**
   - 예: 왜군 병사 그림을 바꾸고 싶다 → 새 그림을 `soldier_japan.webp` 라는
     **똑같은 이름**으로 저장해서 `assets/images/` 안의 기존 파일 위에 덮어씌우면 됩니다.
   - 다른 이름(`soldier_japan2.png` 등)으로 저장하면 안 됩니다. 앱이 그 파일을 알지 못합니다.
   - 이미지 편집 프로그램(그림판, 미리캔버스, 파워포인트 "다른 이름으로 저장" 등)에서
     내보낼 때 **파일 형식을 WebP로** 선택해 주세요. (WebP를 지원하지 않는 프로그램이면
     PNG로 저장한 뒤 [squoosh.app](https://squoosh.app) 같은 무료 사이트에서 WebP로
     바꿀 수 있습니다.)

깃허브는 이미지 같은 파일을 "있는 그대로" 저장하기 때문에, 텍스트 파일과 달리
복사·붙여넣기 과정에서 깨질 걱정이 없습니다. 아래 1번 단계에서 설명하는
"파일 올리기(업로드)" 방식만 그대로 따라 하시면 이미지가 깨질 일은 없습니다.

## 1. 깃허브(GitHub)에 올리기 — 터미널·명령어 없이, 마우스로만!

깃허브는 이 앱의 파일들을 보관하는 온라인 저장소입니다. 계정만 있으면 됩니다.

1. [github.com](https://github.com) 에 접속해서 회원가입/로그인합니다.
2. 오른쪽 위 **+** 버튼 → **New repository** 를 클릭합니다.
3. **Repository name** 에 원하는 이름을 입력합니다. 예: `imjin-war-game2`
   - **Public** 으로 두시면 됩니다. (Vercel 무료 배포에 편리합니다)
   - 아래 "Add a README file" 체크박스는 **체크하지 마세요.** (이미 우리가 만든
     README.md를 쓸 것이기 때문입니다)
4. **Create repository** 를 누릅니다.
5. 새로 생긴 빈 저장소 화면에서 **"uploading an existing file"** 이라는 파란 글자
   링크를 클릭합니다. (화면에 안 보이면 저장소 메인 화면의 **Add file → Upload files**
   버튼을 눌러도 같은 화면이 나옵니다.)
6. 컴퓨터에서 **이 프로젝트 폴더(`imjin-war-game2`) 안의 내용물 전체**를
   (폴더 자체가 아니라 `index.html`, `css`, `js`, `assets`, `apps-script`, `README.md`
   전부를 함께 선택) 그 화면으로 **드래그 앤 드롭**합니다.
   - 폴더째로 끌어다 놓아도 대부분의 최신 브라우저(Chrome)는 하위 폴더까지 함께
     올려줍니다. 만약 `css`, `js`, `assets` 폴더가 통째로 안 올라간다면, 폴더를 하나씩
     열어서 그 안의 파일들을 다시 끌어다 놓아 주세요.
7. 아래 **Commit changes** 초록 버튼을 누르면 업로드가 끝납니다.
8. 저장소 페이지를 새로고침해서 `index.html`, `css`, `js`, `assets`, `apps-script`
   폴더가 잘 보이는지 확인하세요.

이제 이미지·코드가 모두 깃허브에 안전하게 저장되었습니다. (컴퓨터가 고장 나도 사라지지
않습니다!)

## 2. Vercel로 학생들에게 배포하기

Vercel은 깃허브 저장소를 그대로 가져와서 인터넷 주소(링크)로 바꿔주는 무료 서비스입니다.

1. [vercel.com](https://vercel.com) 접속 → **Continue with GitHub** 로 로그인합니다.
   (방금 만든 깃허브 계정으로 로그인하면 됩니다)
2. 로그인 후 **Add New… → Project** 를 클릭합니다.
3. 방금 만든 저장소(`imjin-war-game2`)를 찾아서 **Import** 를 누릅니다.
4. 설정 화면이 나오는데, **아무것도 바꾸지 말고** (Framework Preset이 "Other"로
   나와도 괜찮습니다 — 이 앱은 순수 HTML/CSS/JS라서 별도 빌드가 필요 없습니다)
   그대로 **Deploy** 버튼을 누릅니다.
5. 1분 정도 기다리면 "축하합니다!" 화면과 함께 `https://imjin-war-game2-xxxx.vercel.app`
   같은 주소가 생성됩니다. 이 주소를 학생들에게 나눠주면 크롬북 어디서든 접속해서
   플레이할 수 있습니다.
6. (선택) Vercel 프로젝트 설정의 **Domains** 메뉴에서 더 짧고 기억하기 쉬운 무료
   주소(예: `우리반-임진왜란.vercel.app`)로 바꿀 수도 있습니다.

> 이후 그림이나 문제 내용을 수정하고 싶을 때는, 깃허브 저장소에서 해당 파일만
> 다시 업로드(같은 이름으로 Upload files)하면 Vercel이 몇십 초 안에 **자동으로
> 새 버전을 다시 배포**합니다. 별도 조작이 필요 없습니다.

## 3. 구글 시트와 연결하기 (점수·순위·승리 요인 자동 수집)

이 과정을 마치면, 학생이 마지막 화면에서 제출 버튼을 누를 때마다 선생님의 구글
시트에 학번·이름·승리 요인 서술·점수가 자동으로 쌓입니다.

### 3-1. 구글 시트 만들기

1. [sheets.google.com](https://sheets.google.com) 에서 새 스프레드시트를 만듭니다.
   이름은 자유롭게 정하세요. (예: "임진왜란 시뮬레이터 기록부")
2. 시트는 비워 둔 채로 다음 단계로 넘어가면 됩니다. (첫 실행 시 스크립트가 자동으로
   "기록" 이라는 탭과 제목 줄을 만들어 줍니다)
   - ⚠️ 이전 버전(승리요인을 4칸으로 나눠 받던 버전)의 Code.gs를 이미 시트에
     연결해서 학생 기록이 쌓여 있다면, 아래 3-2단계로 코드를 바꿔 넣기 전에
     기존 "기록" 탭의 이름을 "기록(이전)" 등으로 바꿔 두세요. 열 구성이
     바뀌었기 때문에, 새 이름의 "기록" 탭을 스크립트가 새로 만들도록 해야
     이전 데이터와 섞이지 않습니다.

### 3-2. Apps Script 코드 붙여넣기

1. 방금 만든 시트 화면에서 상단 메뉴 **확장 프로그램 → Apps Script** 를 클릭합니다.
2. 새 탭이 열리면, 기존에 있던 `function myFunction() {}` 같은 코드를 전부 지웁니다.
3. 이 프로젝트의 `apps-script/Code.gs` 파일을 텍스트 편집기(메모장 등)로 열어서
   내용을 전부 복사한 뒤, Apps Script 편집 화면에 붙여넣습니다.
4. (선택이지만 권장) 코드 맨 위쪽의 다음 줄을 확인하세요.
   ```
   const ADMIN_KEY = '1592';
   ```
   이 값은 앱의 `js/config.js` 파일 안에 있는 `ADMIN_PIN` 값과 **반드시 똑같아야**
   "교사용 → 전체 기록 초기화" 버튼이 정상 작동합니다. 원하는 숫자로 바꾸실 거라면
   두 파일 모두 같은 숫자로 바꿔주세요.
5. 왼쪽 위 프로젝트 이름("제목 없는 프로젝트")을 원하는 이름으로 바꾸고,
   저장 아이콘(💾) 또는 Ctrl+S 를 눌러 저장합니다.

### 3-3. 웹앱으로 배포하기

1. Apps Script 화면 오른쪽 위 파란색 **배포(Deploy) → 새 배포(New deployment)** 를
   클릭합니다.
2. "유형 선택" 옆 톱니바퀴(⚙️) 아이콘을 눌러 **웹 앱(Web app)** 을 선택합니다.
3. 아래처럼 설정합니다.
   - **다음 사용자 권한으로 실행(Execute as)**: `나(내 이메일)`
   - **액세스 권한이 있는 사용자(Who has access)**: `모든 사용자 (Anyone)`
     - ⚠️ 이 항목은 꼭 "Anyone"으로 선택해야 학생들의 크롬북에서 점수 전송이 됩니다.
       (Google 계정 로그인을 요구하는 옵션을 고르면 전송이 실패합니다)
4. **배포(Deploy)** 를 누릅니다. 처음 배포할 때 "권한 검토"창이 뜨면
   본인 구글 계정으로 로그인 → "고급" → "(프로젝트 이름)(으)로 이동" →
   허용을 눌러 진행합니다. (본인이 만든 스크립트이므로 안전합니다)
5. 배포가 끝나면 **웹 앱 URL**이라는 주소가 나옵니다.
   `https://script.google.com/macros/s/ABC.../exec` 같은 형태입니다. 이 주소를
   복사해 두세요.

### 3-4. 앱에 주소 연결하기

1. 이 프로젝트 폴더의 `js/config.js` 파일을 텍스트 편집기로 엽니다.
2. `APPS_SCRIPT_URL: ""` 부분의 큰따옴표 안에 방금 복사한 주소를 붙여넣습니다.
   ```js
   APPS_SCRIPT_URL: "https://script.google.com/macros/s/ABC.../exec",
   ```
3. 저장한 뒤, 깃허브 저장소로 가서 **이 파일 하나만** 다시 업로드합니다.
   (저장소 페이지에서 `js/config.js` 클릭 → 연필(✏️) 아이콘 → 내용을 새 내용으로
   바꾸고 **Commit changes**)
4. Vercel이 자동으로 새 버전을 배포합니다 (몇십 초 소요). 이후 학생 화면에서
   "⚠ 아직 구글 시트 주소가 설정되지 않았습니다" 라는 경고 문구가 사라지면 성공입니다.

### 3-5. 연결 테스트

- 아무 크롬북(또는 본인 컴퓨터)에서 앱 주소로 들어가 학번/이름을 입력하고 아무
  전투나 끝까지 진행한 뒤, 마지막 "전적 기록부" 화면에서 승리 요인을 서술형으로
  적고 **[승리 요인 + 점수 제출하기]** 를 눌러 보세요. "제출 완료!" 메시지가 뜨고,
  구글 시트의 "기록" 탭에 한 줄이 추가되면 성공입니다.
- 상단의 **🏆 순위표** 버튼을 눌러서 방금 제출한 기록이 보이는지도 확인해 보세요.

## 4. 학생·교사 사용법 요약

**학생 화면**
1. 학번·이름 입력 후 "출전하기"
2. 각 전투마다: 브리핑 읽기 → 역사 퀴즈 풀기 → 미니게임 플레이 → 결과 확인
   (미니게임은 전투당 1회 "다시 도전" 기회가 있고, 더 높은 점수가 기록됩니다)
3. 8개 전투를 모두 마치면 "전적 기록부"(최종 보고서) 화면이 나옵니다.
   - 여기서 학생이 **승리 요인을 서술형(최소 20자)** 으로 자유롭게 작성합니다.
   - **[승리 요인 + 점수 제출하기]**: 서술한 승리 요인 + 최종 점수를 함께 구글 시트로 전송
   - **[점수만 다시 보내기]**: 이미 제출한 승리 요인 서술은 그대로 둔 채 점수만 다시 전송
     (미니게임을 나중에 다시 해서 점수를 올렸을 때 사용)
   - 학생의 진행 상황은 **그 크롬북에만** 저장됩니다(로컬 저장). 다른 컴퓨터로
     접속하면 처음부터 다시 시작해야 합니다.
4. 상단 **🏆 순위표** 버튼으로 전체 학생의 점수 순위를 언제든 확인할 수 있습니다.

**교사 화면**
- 상단의 **[교사용]** 버튼 → `js/config.js`에서 설정한 관리자 번호(기본값 `1592`) 입력
- 핵심 탐구 과제(학생 화면에는 질문만 보이는 3문항)의 예시 답안을 확인할 수 있습니다.
- **[전체 기록 초기화]** 버튼으로 구글 시트에 쌓인 모든 학생 기록을 한 번에 지울 수
  있습니다. (되돌릴 수 없으니 학기 말이나 반이 바뀔 때만 사용하세요)

## 5. 문제가 생겼을 때

**그림이 안 보이고 빈 공간만 나와요**
→ 브라우저에서 F12(개발자 도구) → Console 탭을 열어 빨간 글씨 오류를 확인하세요.
`[이미지 로드 실패]` 라는 메시지가 보이면, 해당 파일 이름이 `assets/images/` 폴더
안에 정확히 있는지, 대소문자까지 똑같은지 확인하세요.

**"구글 시트 주소가 아직 설정되지 않았습니다" 라고 계속 나와요**
→ 3-4단계에서 `js/config.js`의 `APPS_SCRIPT_URL`을 저장하고 깃허브에 다시 올렸는지,
Vercel이 재배포를 마쳤는지 확인하세요. (Vercel 프로젝트 화면의 "Deployments" 탭에서
가장 최근 배포가 "Ready" 상태인지 볼 수 있습니다)

**"전송 실패: 네트워크 오류..." 가 나와요**
→ Apps Script 배포 설정에서 "액세스 권한이 있는 사용자"가 **Anyone(모든 사용자)**
으로 되어 있는지 다시 확인하세요. 설정을 바꿨다면 **새 배포**가 아니라 기존 배포의
**배포 관리 → 수정(연필 아이콘) → 버전: 새 버전** 으로 다시 배포해야 주소가
유지된 채 반영됩니다.

**전체 기록 초기화가 "관리자 번호가 올바르지 않습니다" 라고 나와요**
→ `js/config.js`의 `ADMIN_PIN`과 `apps-script/Code.gs`의 `ADMIN_KEY` 값이 서로
다릅니다. 두 값을 똑같이 맞춘 뒤, Code.gs는 Apps Script 편집기에서 저장 후
**새 버전으로 재배포**해야 적용됩니다.

**학생이 실수로 새로고침하거나 크롬북을 바꿨어요**
→ 진행 상황은 학생의 그 크롬북 브라우저에만 저장되므로, 같은 크롬북·같은 브라우저로
다시 들어가면 "이어하기" 버튼이 나타납니다. 다른 기기로는 이어할 수 없고 처음부터
다시 진행해야 합니다.
